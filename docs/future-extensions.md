# 未来扩展（Future Extensions）

**状态：** 待定 / 暂缓。以下内容是从主线规划中剥离出来的「游戏助手」扩展愿景，**不属于当前 MVP 范围**。等 AI 副屏、金手指、存档、事件录像等基础功能完成后再单独评估。

**主线规划见：** [transformation-plan.md](transformation-plan.md)、[phase0-task-breakdown.md](phase0-task-breakdown.md)。

## 概述

原路线图中，项目被定位为「面向玩家的游戏助手」，除当前的基础功能（AI 副屏、金手指、存档、事件录像）外，还规划了若干扩展工作包。这些扩展属于更宏大的「游戏助手」愿景，尚未实现、尚未独立设计，现统一归档至此，作为未来参考，不阻塞基础功能交付。

## 后续工作包 A：攻略与设定集 PDF/OCR 知识库（待独立设计）

### 目标与入口

玩家在本机显式导入有权使用的 PDF。优先提取已有文字层；仅对扫描页或低质量文字层按页执行有预算的 OCR。与现有 CT RAG、存档观察、游戏版本建立**带来源的关联**，不得把攻略文本或 OCR 结果提升为游戏事实、模型指令或存档/内存写入权限。

### 设计与验收门禁

- 先形成独立设计与实施计划，明确支持的 PDF 类型、文字语言、OCR 引擎/模型及再分发许可证、离线/联网处理边界、文件大小/页数/耗时预算、密码保护与损坏文件处理。
- 摄取记录文件哈希、许可证/用户来源、页码与页面区域、解析/OCR 方法及版本、置信度、未处理页和索引鲜度；OCR 不确定内容必须在引用问答中标明，不能伪造页码或引用。
- 玩家可选择剧透边界；查询和模型披露只使用获授权的文档范围。删除或替换 PDF 后，旧索引不得继续作为新鲜结果返回；提供重建与撤销入口。
- 验收含文字层、纯扫描页、混合页、双栏、旋转、低清、错字、受保护/损坏/超预算文件；UI 显示摄取进度、覆盖率、错误与原页引用，MCP 只提供受控查询。未经真实样本与人工页码对照，不宣称 OCR 达到商业级质量。
- 依赖：存档状态视图和权限/来源边界稳定；可以先写规格与夹具测试，但不据此提前解除当前 Gate 9。

## 后续工作包 B：玩家自带 Live2D 虚拟形象导入（待独立设计）

### 目标与入口

在 Windows 原生工作台提供“导入已有 Live2D 模型包、预览、启用、撤销”的本机流程。这里指导入玩家提供的模型文件，**不是**从单张图片自动生成 Live2D 模型，也不是让模型文件获得 AgentOS 工具权限。虚拟形象承担展示和交互反馈，不作为审批或任务完成的唯一提示渠道。

### 设计与验收门禁

- 独立设计先确定支持的 `model3.json`/`moc3`、纹理、动作、表情及运行时版本矩阵，选择可合法商用/再分发的渲染组件并核实用户模型的使用授权；未知或不兼容包可拒绝，不做静默转换。
- 导入前检查包大小、文件类型、路径穿越/符号链接、外部引用、纹理尺寸和资源预算；把模型数据当非可信内容处理，不执行随包脚本或任意命令。预览在隔离资源边界中进行，加载失败不影响游戏工作台主流程。
- UI 提供模型来源、版本/兼容性、缺失资源、性能降级和一键禁用；动作/表情与助手状态的映射可由玩家关闭，审批、错误、取消等关键信息仍以文字可访问形式呈现。
- 验收含有效/缺纹理/路径逃逸/损坏/超预算/版本不兼容模型、长时间运行与显存/CPU 降级；在干净 Windows 环境做导入、预览、卸载/清理和原生 UI 点击测试。不把演示模型或第三方素材打包进商业版本，除非许可证明确允许。
- 依赖：Windows 工作台稳定；可与 PDF/OCR 分别设计和实施，但不以 Live2D 阻塞核心单机工具的安全修复。

## 工作包：Android 候选阶段启动条件（暂不排期）

Android 工作必须等待 Gate 9 且由用户单独确认是否启动，除非只进行不影响 Windows 交付的契约验证。PDF/OCR 与 Live2D 的 Windows 工作包不隐含 Android 适配承诺。

### 启动任务

1. 从 Windows 已验证行为提取平台 conformance suite。
2. 决定 Android 宿主技术栈和进程/Root 信任边界。
3. 完成所有参考仓库许可证决策；授权不明确代码只读不复制。
4. 实现只读 process/map/read/scan capability prototype。
5. 通过相同 Experiment/Evidence/Recipe 行为测试后，再设计 Android 写入审批 UX。

## 后续工作包 C：商业发布与维护门禁（跨工作包，未通过）

> 注：商业发布门禁本身**不属于「游戏助手」扩展愿景**，而是主线功能完成后必须通过的发布质量门。此处仅作索引，具体以 `docs/delivery/windows-release-playbook.md`、`docs/delivery/verification-report.md` 为准。

商业级是每个功能的质量要求，不是“能编译/能演示”或拥有 Live2D 界面就达成。正式公开发布前应建立可追溯的需求→测试→用户入口矩阵，完成受支持 Windows 版本与普通权限环境、安装/升级/卸载、异常恢复、真实游戏与真实文档/模型样本、性能预算、无障碍与本地化、隐私数据清理、第三方许可证/SBOM、供应链与安全审查、签名及 Defender 告警处置、诊断/支持和回滚验证。当前未取得商业发布验收，不对外宣称已可正式销售或分发。

## 数据流定位（原存档架构中的预留）

原存档架构规格中预留了扩展接入的数据流：

```
下一阶段：攻略/设定集摄取 -> Knowledge Evidence -> Game State Projection
```

其中 `GameStateProjection` 定义：来自存档/内存/CT/后续攻略的分层观察和冲突，附来源与鲜度；**不是第二份权威状态**。攻略结论是 Evidence，不能自动改存档。此定位仅作未来参考。
