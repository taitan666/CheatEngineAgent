# Game Companion Console — UI/UX 设计规范

**基于：** `ui-ux-pro-max` 设计智能库 + PRD V1.2 第 7 章线框 + 现有 Lazarus 原生窗口
**日期：** 2026-10-19
**状态：** 设计建议，供副屏网页运行时与桌面主窗口重组（Phase 1 的 1D/1H）实施参考

---

## 1. 设计定位

**产品是「AI 游戏副屏 + 智能修改器」**：一个给 PC 玩家在第二屏查看/编辑游戏状态的工具型软件。它**不是**游戏内 HUD 仿制品（PRD 7.9 明确要求避免），而是深色、工具型、信息密度适中的控制台。

两条 UI 表面：
1. **桌面主窗口**（Lazarus 原生，三栏布局）——管理侧：游戏概览、副屏生成、字段详情、金手指实验室、Profile、设置。
2. **副屏网页**（WebView2 / 本地受限容器）——展示+交互侧：宽屏游戏状态控制台，默认 16:9。

---

## 2. 设计系统（design_recommend 产出，已对齐产品）

### 2.1 风格

**首选：Modern Dark（Cinematic Mobile）**，落地到桌面/宽屏场景：

- 深色影院级背景 + 环境光晕（ambient light）+ 玻璃拟态标题栏/导航
- 关键气质：`deep black`（避免纯 `#000000`）、`indigo` 主色、`glow` 光晕、`frosted glass`、`layered` 分层
- **克制原则（PRD 7.9）**：工具型、信息密度适中，动效克制（motion 3/10），不做炫技

**次选**：Soft UI Evolution（浅色模式 fallback，用于「深浅色模式都支持」）。

### 2.2 配色方案（语义令牌，禁止逐屏硬编码）

| 角色 | HEX | 用途 |
| --- | --- | --- |
| 主色 primary | `#7C3AED` | 主按钮、焦点环、选中态、连接状态「已连接」 |
| 主色前景 | `#FFFFFF` | 主按钮文字 |
| 次色 secondary | `#A78BFA` | 次要强调、进度条渐变、hover |
| 强调/CTA | `#F43F5E` | 「应用修改」确认按钮（危险但非破坏性动作的注意力色） |
| 背景 bg | `#0F0F23` | 全局背景（非纯黑） |
| 前景文字 fg | `#E2E8F0` | 正文 |
| 卡片 surface | `#1E1C35` | 卡片/面板背景 |
| 弱化 muted | `#27273B` | 次表面、禁用态背景 |
| 边框 border | `#4C1D95` | 分隔线、卡片描边（rgba 半透明更佳） |
| 危险 danger | `#EF4444` | 删除、恢复（不可逆）、错误态 |
| 焦点环 focus | `#7C3AED` | 键盘焦点可见 |

**语义映射（关键，对应 PRD 字段状态）：**

| 字段读写状态 | 颜色 + 图标（颜色不能是唯一信号，PRD 7.9） |
| --- | --- |
| 只读 read_only | 次色 `#A78BFA` + 「锁」图标 + 文字「只读」 |
| 待验证 pending_write | 琥珀/警告色 + 「时钟」图标 + 文字「待验证」 |
| 已验证可写 verified_writable | 主色/绿色 + 「笔」图标 + 文字「可写」 |
| 失效 invalid | 危险色 `#EF4444` + 「警告」图标 + 文字「失效」 |
| 执行失败 | danger + 具体原因文字（PRD 7.4 失败状态分级） |

### 2.3 字体

- **标题/数值/代码**：Fira Code（等宽，数据面板 + 十六进制地址/AOB 显示需要等宽）
- **正文/标签**：Fira Sans
- 搭配名「Dashboard Data」——dashboard/data/analytics/technical/precise，正中工具型控制台气质
- Google Fonts：`Fira Code 400-700 + Fira Sans 300-700`，`font-display: swap`

### 2.4 间距刻度（4/8dp 节奏）

```
space-xs = 4px   space-sm = 8px   space-md = 16px
space-lg = 24px  space-xl = 32px  space-2xl = 48px  space-3xl = 64px
```

### 2.5 动效（克制，motion 3/10）

- 页面/标签切换：`opacity` 淡入淡出 200-300ms，`power1.inOut`
- 按压反馈：scale 0.97 → 1.0，80-150ms 内响应，不改变布局边界
- 数值变化：仅在「字段值变化」时做一次短暂的数值高亮（150-300ms），**不做**持续动画（PRD 要求 AI 不每帧推理、采集轻量）
- 支持 `prefers-reduced-motion`，尊重系统减少动态设置

## 3. 副屏网页设计（PRD 7.2 / 7.6 线框落地）

### 3.1 布局骨架（16:9 宽屏优先，响应式网格，不硬编码固定坐标）

```
┌────────────────────────────────────────────────────────────────┐
│ 顶栏：游戏名 · 连接状态● · 最后更新 18:07:32  [刷新][布局][只读模式] │
├──────────────┬──────────────────────────────┬─────────────────┤
│ 左栏 页面导航 │ 主内容区（当前页面）           │ 右栏 详情与操作    │
│ 概览/角色/背包│ 属性卡 / 装备槽 / 物品格 / 表格 │ 当前选中项详情     │
│ 装备/地图/任务│ 进度条 / 地图占位             │ 数据来源·状态     │
│              │                              │ [符合条件时显示编辑]│
├──────────────┴──────────────────────────────┴─────────────────┤
│ 底栏：操作反馈 / 命令已发送 / 验证成功 / 失败原因（PRD 7.4 分级） │
└────────────────────────────────────────────────────────────────┘
```

### 3.2 组件规则（FR-021 组件库 + PRD 7.6 生成规则）

| 组件 | 默认只读表现 | 已验证可写后 | 备注 |
| --- | --- | --- | --- |
| 数值（HP/MP/金币） | 数值 + 进度条 | 数值输入框 + 应用按钮 | 进度条用次色渐变 |
| 布尔/开关 | 状态标签 | 开关控件 | 按压反馈明确 |
| 枚举 | 当前值文本 | 下拉选择 | 仅存在有效候选项时 |
| 物品数量 | 数量标签 | 数量输入框 | — |
| 装备槽 | 装备名 + 图标 | 替换操作（适配器支持后） | — |
| 未知字段 | 原始值 + 来源 + 「需要确认」 | 不生成写入控件（FR-022/AC-005） | — |
| 地图 | 占位说明 / 已知标记 | 不虚构地图（PRD 7.6） | — |

**硬规则（对齐 PRD）：**
- 只读字段**不能**渲染成可提交的编辑控件；不可操作时不显示误导性按钮。
- 未验证字段编辑控件隐藏或禁用，并解释原因。
- 「命令已发送」≠「修改成功」，底栏必须区分两级反馈（PRD 7.4）。

### 3.3 修改确认弹窗（PRD 7.3 / 7.8）

```
┌────────── 应用修改 ──────────┐
│ 字段：当前生命值              │
│ 游戏版本：已匹配 ｜ 来源：内存  │
│ 验证状态：已验证可写           │
│                              │
│ 当前值 [ 100 ]   目标值 [ 500 ]│
│ 允许范围：由适配器/已验证约束提供│
│                              │
│ ☑ 重新读取并验证实际结果       │
│           [取消] [确认应用]    │
└──────────────────────────────┘
```

- 交互状态：执行中禁用按钮显示「正在提交」；命令已发送→「等待验证」；验证成功→「验证成功」；验证失败→具体原因（游戏未接受/被覆盖/连接断开/版本失效）。
- 状态冲突：当前值在编辑期间变化时，要求刷新后重新确认（FR-045）。
- 二次确认：高风险/批量/不可逆操作用 danger 色 `#F43F5E` CTA（FR-043）。

## 4. 桌面主窗口设计（PRD 7.1 / 7.5 线框，Lazarus 原生）

### 4.1 三栏布局（1440×900，低分辨率可折叠侧栏）

```
┌─────────────────────────────────────────────────────────────┐
│ Game Companion Console  [当前游戏▼] ●已连接 只读模式 [设置][帮助] │
├──────────────┬──────────────────────────┬──────────────────┤
│ 左侧导航      │ 中央工作区                │ 右侧字段详情       │
│ 游戏概览      │ 连接状态卡/字段统计卡     │ 当前字段语义/类型  │
│ 副屏页面      │ 副屏网页预览              │ 来源/置信度/验证   │
│ 数据字段      │ 最近变化/AI建议/诊断      │ 允许操作/更新时间  │
│ 金手指实验室  │ 事件采集状态/缓存占用     │ [查看证据][编辑映射]│
│ Game Profile │                          │ [打开副屏]        │
│ 操作历史      │                          │                  │
│ 事件时间线    │                          │                  │
│ 设置         │                          │                  │
└──────────────┴──────────────────────────┴──────────────────┘
```

### 4.2 关键状态可视化（复用 2.2 语义映射）

- 顶栏连接状态：`● 已连接`（主色）/ `● 只读模式` / `● 版本不匹配`（danger）
- 字段统计卡：「已识别字段 / 待确认 / 已验证可写」三色数字卡
- 金手指实验室候选状态（PRD 7.7）：未验证/观察到变化/多轮验证通过/写入待批准/已验证可写/版本失效/已禁用——用文字+图标，不用纯颜色

### 4.3 与现有 Lazarus 窗口的关系

现有 `cea_main_form.pas` 已有 7 个 Tab（AgentOS/进程内存/CT RAG/存档/LLM/MCP/关于安全），这些是**底层诊断页**。PRD 重组为玩家级三栏时：

- **保留**：进程内存、存档、LLM、MCP、关于安全（作为「底层/诊断」次级页）
- **新增玩家级**：游戏概览、副屏页面、数据字段、金手指实验室、Game Profile、操作历史、事件时间线
- 主色 `#7C3AED` 用 Lazarus 的 `TColor` 表达；副屏网页用 CSS 变量（§2.2 的 HEX）

## 5. 无障碍与交付前检查（design_review 产出，重点条目）

### 严重/高优先级（必须做）

1. **触摸/点击目标 ≥ 44×44pt**（副屏网页按 WCAG 2.5.8 的 24×24 CSS px 单独评估）
2. **键盘导航完整**：tab 顺序对齐视觉顺序，每个可操作控件有可见焦点（`focus-visible`），无键盘陷阱
3. **对比度**：深色正文 ≥ 4.5:1，次要文字 ≥ 3:1（深色模式**独立测试**，不推断）
4. **颜色不是唯一信号**：字段状态用「颜色 + 图标 + 文字」三重表达（PRD 7.9 明确要求）
5. **避免水平滚动**：副屏内容适配视口宽度

### 中优先级

6. 字体 `font-display: swap`，避免不可见文字
7. 缓存策略（副屏页面本地服务，重复打开要快）
8. bundle 大小控制（受控组件库，不用重型框架）

### 交付前通用清单（对齐 ui-ux-pro-max）

- [ ] 无 emoji 作结构图标（用 Phosphor / Lucide 矢量图标，统一线性风格）
- [ ] 图标尺寸令牌 icon-sm/md/lg，与文字基线对齐
- [ ] 按压反馈 80-150ms，不改变布局边界，可点击元素 `cursor:pointer`
- [ ] 深浅色模式都测（浅色用 Soft UI Evolution fallback）
- [ ] 空状态/加载态（骨架屏）/错误态/禁用态都设计（不只 happy path）
- [ ] 表单内联校验、错误信息具体可操作（不只标红）
- [ ] 长列表虚拟化（物品格/候选地址列表）
- [ ] 支持 `prefers-reduced-motion` 与动态字体

## 6. 关键设计决策（含理由）

| 决策 | 理由 |
| --- | --- |
| 主色用霓虹紫 `#7C3AED` 而非游戏常见绿 | 与「工具型控制台」气质匹配，绿色留给「已验证可写/成功」语义，避免混淆 |
| 强调色用玫瑰 `#F43F5E` 做「应用修改」CTA | 写入是高风险动作，需要注意力色；但通过文字+图标区分「破坏性」（danger 红）与「可逆修改」（玫瑰） |
| 数字/地址用 Fira Code 等宽 | 内存地址、AOB、hex、数值对齐是修改器核心，等宽字体是硬需求 |
| 动效克制（3/10） | PRD 7.9 明确「工具型、不炫技」+ 采集要轻量、不每帧刷新 |
| 副屏默认深色、支持浅色 fallback | PRD 7.2「默认深色游戏控制台」，但无障碍要求深浅双测 |
| 字段状态三重表达（颜色+图标+文字） | PRD 7.9 硬要求「不能只靠颜色表达」 |

## 7. 反模式（design_recommend 产出，结合 PRD）

- ❌ 极简主义 Minimalist（产品需要信息密度适中的控制台，不是留白极简页）
- ❌ 静态资产（状态是实时变化的，需要动态反馈）
- ❌ 纯黑 `#000000` 背景（OLED 拖影）
- ❌ 把「命令已发送」误报为「修改成功」（PRD 7.4 底线）
- ❌ 未验证字段显示可提交的编辑控件（FR-022/AC-005 底线）
- ❌ 用纯颜色表达状态（PRD 7.9 底线）
- ❌ 虚构地图/不存在的数据（PRD 7.6 底线）
