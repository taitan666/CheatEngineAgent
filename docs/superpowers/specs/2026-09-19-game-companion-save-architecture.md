# AI 游戏助手：格式无关的存档架构

日期：2026-09-19  
状态：用户已确认的设计；不代表存档编辑功能已实现  
范围：独立 Windows/Lazarus 应用中的存档读取、备份和受控编辑；攻略知识库等扩展愿景见 [未来扩展](../future-extensions.md)

## 1. 意图与本期边界

产品从一开始就定位为了解游戏与玩家进度的 AI 游戏助手。本期先建立安全、可恢复的存档能力，把 CT RAG、存档观察与进程状态接入同一游戏状态视图。现有 CT RAG、进程只读能力、受控内存 Effect 和 MCP 保留，不迁移回原版 Cheat Engine；攻略 PDF、Live2D、语音、Android 等扩展愿景见 [未来扩展](../future-extensions.md)，不属本期。

本期的可验证成果是：用户可选择自己有权操作的单机离线存档，查看文件身份与可解析字段，生成不可变备份；仅当某个格式适配器明确支持版本、字段、校验及重编码时，才允许通过本机审批进行一次字段级修改，并用重新打开文件的独立读回验证结果。没有真实游戏样本时，只能用自有测试格式验证框架，不能宣称支持真实游戏存档。

永久边界：不触碰联网/多人服务端状态、反作弊绕过或隐蔽修改；不训练、微调或改写模型权重。历史对话、存档正文与模型输出均是非可信输入，不能授予权限或成为执行指令。

## 2. 方案选择

选择“通用文件安全底座 + 已注册的游戏格式适配器”。

| 路线 | 优点 | 主要风险 | 本期决定 |
|---|---|---|---|
| 任意文件由 AI 猜偏移后写回 | 看似覆盖广 | 校验和、压缩、版本与字段语义未知，极易损坏存档 | 禁止自动写回 |
| 只支持一种明文格式 | 易于快速演示 | 通用能力和治理边界不清 | 仅用作测试适配器 |
| 通用底座 + 版本化格式适配器 | 通用治理可复用，每款游戏单独证明正确性 | 首个真实游戏适配器仍需样本和验收 | 采用 |

未知、加密、压缩、带签名或校验规则不明的格式可以被安全识别、备份并作有限只读展示；不得仅凭 AI 推断进入写入路径。检测到云同步、游戏正在写同一文件、目标身份变化或路径歧义时，编辑拒绝并要求用户处理冲突。

## 3. 组件和依赖

```text
Windows 原生工作台 / MCP（查询与提议）
  -> Save Application Service（任务与用户可见投影）
      -> Save Domain（快照、字段、差异、版本、恢复语义）
      -> Local State / Governance / Execution Services
          -> Save File Port（受治理的实际文件效果出口）
      -> Format Registry（探测与精确版本选择）
          -> Read-only Inspector / Game-specific Codec
      -> Backup Store（内容寻址、保留与恢复材料）

Save Domain 不依赖 Win32 句柄、Lazarus 控件、具体游戏、MCP 或模型 SDK。应用自身的状态与治理服务保持权威状态；原始存档由玩家文件系统持有，备份为独立不可变 Artifact，解析字段、进度摘要和 RAG 索引只是带来源的派生视图。CT、内存与存档观察可在同一 `GameSession` 下并列展示，但不能因为值相似就自动断定它们是同一个事实。

MCP 只可列出能力、读取已授权的脱敏状态、请求备份或生成待审批编辑提议；不得远程批准、绕过本机确认或直接调用文件写口。LLM 只生成 `SaveEditProposal`，不传入任意文件路径/字节序列作为写命令。

## 4. 格式无关契约

所有对象含稳定 ID、`schema_version`、来源、时间和内容摘要。实现时为下列对象建立 Schema 与 Pascal 类型；这里固定语义，不伪称机器 Schema 已存在。

| 对象 | 必需语义 |
|---|---|
| `SaveTarget` | 用户选择的授权范围、规范化路径、文件身份、游戏声明、离线声明；路径本身不是信任凭据 |
| `SaveSnapshot` | 读取时的字节长度、SHA-256、文件身份/版本、采集时间、适配器探测结果和读取覆盖率 |
| `SaveFormatDescriptor` | 游戏/格式标识、支持版本、探测规则、字段 Schema、序列化与校验能力、适配器版本/摘要、读写能力声明 |
| `SaveFieldObservation` | 字段稳定路径、类型、值或脱敏摘要、字节/记录来源范围、解码置信度、快照引用；默认是 Observation |
| `SaveBackup` | 原始快照的不可变副本、哈希、存储位置引用、创建原因、恢复可用性、保留策略 |
| `SaveBackupEffect` | 备份这一文件写入的目标、基线、幂等键、Policy/Lease、Receipt 和备份读回 Proof；可按预先声明的低风险策略自动批准，但不能绕开 Effect |
| `SaveEditProposal` | 基线快照、确切字段路径及预期原值/新值、约束、预期结果、风险、所需审批和适配器绑定；无 Authority |
| `SaveEditEffect` | 内容绑定审批、目标身份、基线哈希、幂等键、预算、备份引用、执行状态及 RecoveryCase 引用 |
| `SaveEditReceipt` / `SaveVerification` | 实际写入/替换结果、前后文件哈希、重新打开读回、字段与校验验证、失败或不确定原因 |
| `GameStateProjection` | 来自存档/内存/CT 的分层观察和冲突，附来源与鲜度；不是第二份权威状态 |

字段路径仅可由选中的适配器 Schema 定义，不能由模型构造一个未注册的偏移或脚本来扩展。适配器必须声明 round-trip 能力：`decode(encode(snapshot, edits))` 通过字段级和未改字段保持性检查；校验、压缩或签名不支持时为只读。任何不完整解析都报告缺口，不把“看见几个字段”称为完整读取。

## 5. 主流程

1. 用户在本机选择具体存档及游戏，确认其为自有、授权、离线使用；服务检查路径作用域、文件身份、大小预算和占用状态。
2. 只读复制/打开得到 `SaveSnapshot`；记录哈希、来源与解析覆盖率。格式注册表按内容及版本探测，歧义则拒绝写能力。
3. 在任何编辑提议前，经 `SaveBackupEffect` 向唯一文件写出口创建 `SaveBackup`；记录 Receipt，重新读回备份哈希形成 Proof，并确认可用。备份失败则不能进入编辑 Admission。
4. 适配器把可验证字段解析为 `SaveFieldObservation`。用户或 LLM 可提出字段级差异；提议经字段 Schema、取值范围、跨字段不变量和风险评估校验。
5. UI 展示游戏/槽位、原始与目标值、文件及备份身份、风险、恢复方式；本机用户审批绑定该提议版本、基线哈希、目标身份、策略、次数和有效期。
6. 执行前再次解析文件身份、路径、授权、Lease 和哈希；不一致即拒绝。生成同目录候选文件，在隔离候选上验证结构、校验和、未改字段以及可重新解码性。
7. 将持久化的 `SaveEditEffect` 交付给唯一写出口；写口只按批准的候选摘要提交，并使用可恢复的同卷替换步骤。记录实际操作的 `Receipt`，重新打开目标并独立验证哈希、编辑字段和格式校验，生成 `Proof`。只有通过验收才报告编辑成功。
8. 恢复原存档是新的、独立审批的 Effect：检查当前文件身份与哈希，展示会丢失的变化，按备份版本恢复并读回。不得在失败或退出时悄悄覆盖用户后续进度。

备份文件与原文件不得共用同一路径。临时文件、替换和文件元数据同步的实际顺序由 Windows 文件端口在实现计划中固定，并用故障注入验证；不能仅凭“使用 rename”声称跨所有文件系统原子。云同步客户端可能在本地验证后再次改变文件，应向用户明确本机验证范围。

## 6. 失败、取消和恢复

- 未知格式、模糊版本、校验失败、受保护/重新解析路径、文件被游戏占用、基线哈希变动：只读或拒绝，绝不猜测写入。
- 用户取消：先阻止新的写调用并撤销 Lease；已开始的替换必须记录真实结果，不能把取消当作“未写入”。
- 崩溃窗口：应用启动后只扫描未结算的备份/编辑/恢复 Effect 与候选/备份状态；可读状态进入对账，不能自动继续编辑或恢复。无法证明最终文件状态时保持 `unknown`，建立具名 RecoveryCase。
- 编码成功但替换失败：保留原文件与备份，清理候选需有可核对记录。替换可能成功但回执缺失时，按目标和备份哈希对账，不重复写同一 Effect。
- 读回失败、字段不一致或提交冲突：记录失败/unknown 与证据，禁止宣称成功；用户可选择独立恢复 Effect。日志、LLM 上下文和 MCP 输出不包含完整存档、秘密或不必要的绝对路径。

这些约束是本项目自身的安全与数据完整性要求；如 Schema 或现有实现冲突，应记录差异并单独修订，不得静默放宽治理。

## 7. 验收与交付顺序

本规格是新存档子项目，不把现有 Windows Gate 9 标记完成。实施分成可独立验收的交付：

1. **只读与备份**：测试文件及未知二进制文件均可得到身份/哈希、来源和可验证备份；拒绝路径逃逸、过大文件和不完整读取。
2. **测试格式编辑闭环**：自有夹具格式的字段编辑通过本机审批、候选验证、单次替换、重新打开读回、Receipt/Proof 与独立恢复；异常注入覆盖每个崩溃窗口。
3. **真实游戏适配器**：必须另获具体游戏、版本、授权样本及字段语义；先只读对照，再做最小可恢复修改。没有这些材料，状态保持 `unverified`。

> 攻略知识库、语音、Live2D、长期陪伴等扩展愿景见 [未来扩展](../future-extensions.md)，不属本存档规格的交付范围。

自动化必须覆盖字段合法/非法值、同名不同版本、路径重解析、文件变化竞态、备份失败、替换前后崩溃、重复幂等键、取消、读回失败、恢复冲突、MCP 无审批权及敏感内容不泄漏。报告真实执行命令、结果、适配器覆盖范围和未验证项；夹具通过不等于真实游戏通过。
