# 事件驱动游戏助手闭环：实施计划

**状态：** 待执行；本文中的未勾选项不代表已实现  
**日期：** 2026-10-21  
**规格：** [事件驱动游戏助手闭环](../specs/2026-10-21-game-companion-event-loop.md)

## 目标

在不推翻现有本地治理服务、Windows 内存后端、状态模型、副屏、存档、CT RAG 与事件服务的前提下，补齐从确定性采集到事件证据再到 AI 辅助分析的端到端闭环。

## Phase A — 修复采集正确性

- [x] 将字段变化基线按稳定 FieldId 分开保存，避免交替采集字段时误报变化。
- [x] 让捕获结果的 JSON 布尔值使用小写 `true/false`。
- [x] 对当前进程身份 ID / Epoch 变化显式重置采集基线。
- [ ] 增加同 PID 新 Epoch 的回归测试。
- [ ] 统一 `CapturedAt` 的时间语义：单调时钟用于排序和窗口，UTC 时间用于显示/持久化；禁止把本地时间标为 UTC。
- [ ] 增加专门的 `test_state_capture` 覆盖字段切换、基线重置、失败读取、类型宽度和结果 JSON 合法性。

**退出条件：** 全量 Pascal 回归与编译冒烟通过；跨字段无误报；进程身份变化不会继承旧值。

## Phase B — 连续帧环形缓冲与真实前后录

- [ ] 新增后台 Frame Capture Worker，显式开启后按配置间隔持续抓帧。
- [ ] 修正 Windows 24-bit DIB 的行跨度：DIB stride 必须按 4 字节对齐，不能直接假设为 `width * 3`。
- [ ] 每帧保存真实 `GetTickCount64` 时间戳、序号、尺寸、格式、哈希和捕获错误；帧索引不能只记录总帧数。
- [ ] 使用有界的内存环形缓冲；预算同时限制帧数、总字节数和时间范围。
- [ ] 事件触发时冻结前录引用，进入异步 post-roll，达到截止时间后再 finalise。
- [ ] 事件窗口合并时延长后录截止时间，防止重复片段与同步 UI 阻塞。
- [ ] 增加捕获失败、窗口最小化、目标窗口变化、帧丢失、超预算、取消和删除媒体文件测试。
- [ ] 将当前“关键帧序列”明确显示为帧回放，不宣称是编码视频；后续编码器单独设计。

**退出条件：** 测试能证明至少一帧时间早于触发时刻、至少一帧晚于触发时刻；所有帧时间戳真实且单调；预算耗尽明确返回 partial。

## Phase C — 选定字段的后台采样器

- [ ] 新增 `TCEAStateSamplerService`，只轮询用户 Profile 中显式启用的字段。
- [ ] 定义采样间隔、每轮读取字节、每分钟预算、最大字段数和取消接口。
- [ ] 后台线程只发出不可变的采样结果，不直接访问 LCL 控件。
- [ ] 将采样结果送入状态模型、字段证据服务和 `TCEAEventService.ObserveField`。
- [ ] 目标身份/Epoch 变化、Profile 不匹配或写入权限撤销时停止采样并清空基线。
- [ ] 默认关闭自动采样；增加可见状态、暂停/恢复/停止按钮。
- [ ] 为字段值格式、不可读地址、过期值、读取预算、取消与慢响应添加测试。

**退出条件：** 仅对用户选定字段周期采样；无全进程后台扫描；事件规则无需 LLM 即可稳定触发。

## Phase D — 统一事件证据包与 AI 唤醒策略

- [ ] 在事件包中关联字段差分、前后帧引用、Profile/版本指纹、CT/存档来源引用和用户标签。
- [ ] 区分事件“已捕获”“已入队”“已本地分析”“云端分析待授权”“已分析”“partial/failed”。
- [ ] 默认 Manual；可选 Auto-enqueue；Auto-analyze 需对当前会话显式启用且满足预算。
- [ ] 保留云端每次发送内存值、截图或事件摘要的明确同意门禁。
- [ ] 队列满或模型失败不得阻塞采样/录像；原始证据与模型分析结果分开保存。
- [ ] AI 输出只生成事实/推断分离的摘要和下一步只读观察建议，不能直接发起写入或执行 CT。
- [ ] 增加事件重放、合并、冷却、队列溢出、云端未授权拒绝与 AI 取消测试。

**退出条件：** 同一事件可从本地时间线重现其输入证据；未经同意的数据不会进入云端请求。

## Phase E — 副屏与 Profile 集成

- [ ] 副屏增加事件时间线和帧序列查看入口，显示事件来源与字段差分。
- [ ] 游戏字段、事件和操作记录统一从现有服务投影，不创建第二份权威状态。
- [ ] Profile 保存字段映射、UI Schema、采样/触发规则和兼容性证据。
- [ ] Profile 导入后所有字段默认只读并重新验证；绝不继承写入授权。
- [ ] Profile 分享前移除绝对地址、用户路径、存档、录像、凭据与未授权 CT 内容。
- [ ] 对只读控件、已验证可写控件、版本失效、断连、撤销与键盘可访问性做 UI 验收。

**退出条件：** 副屏能展示状态与事件证据；修改控件只出现在已验证字段上，并且沿用现有 Command Bus 与 Approval 流程。

## 建议文件边界

- `src/core/capture/cea_state_capture_service.pas`：字段基线与单字段读取；保持无 UI 职责。
- `src/core/capture/cea_state_sampler_service.pas`：新增后台采样调度器。
- `src/core/events/cea_event_types.pas`：补充真实帧时间戳、帧引用与事件生命周期状态。
- `src/core/events/cea_event_service.pas`：事件窗口合并、状态差分和 finalise。
- `src/core/events/cea_recording_service.pas`：管理有界媒体引用/淘汰策略，不负责实际捕获。
- `src/core/events/cea_event_recording_bridge.pas`：把帧捕获结果接入缓存并传播错误/partial 状态。
- `src/platform/windows/cea_win32_recording.pas`：DIB stride 修正、帧时间戳和后台采集实现。
- `src/app/cea_application_runtime.pas`：采样会话生命周期、身份变化和显式授权。
- `app/lazarus/cea_main_form.pas`：只负责用户设置与状态展示，不运行采集循环。
- `tests/pascal/test_field_command_flow.pas`：字段切换基线回归。
- 新增采样、帧缓冲、事件窗口、媒体删除和队列策略测试。

## 永久不变量

- 只读扫描不自动升级为写权限。
- 事件触发、截图或 AI 分析均不能自行批准 Effect。
- 未经用户逐次同意，不把内存值/截图/事件包发往云端。
- 不自动执行下载的 CT、AA 或 Lua。
- 不支持多人游戏作弊、反作弊绕过、隐藏或内核驱动能力。
- 未验证的真实存档格式保持只读/备份；真实格式写入需要独立 Codec 验证。
